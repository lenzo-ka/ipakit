# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- `find(ipa, query)`: natural-class search over a transcription — the query language `phones_matching` runs over the inventory, run over the units of a string instead (one resolver, shared, rather than a second dialect). Matches are `(index, Segment)` pairs indexed against `segments()`, so the unit's structure is in hand and `to_ipa()` spells it, and an unresolvable query raises here as it does there instead of reporting every unit. `to_ipa(units)` joins structured units back into one string — the inverse of `segments()`, documented as no stronger than `Segment.to_ipa`: legacy alias spellings come back canonical, and marks belonging to no unit are carried by no Segment. `feature_values(unit)` names the bridge from the flat API to the structured reads — the multi-valued companion of `features()`, which is the scalar one (#22).
- The feature level is writable, not just readable: `to_phone(bundle)` realizes a feature bundle as the registered symbol that names it (the inverse of `features()` — exact on the keys given, free on the keys omitted, ties resolved by fewest declared extras, then fewest constituents, then declaration order), and `respell(phone, **changes)` applies a feature delta and realizes the result (`respell("t", voiced="+")` → `d`, `respell("p", place="velar")` → `k`), returning `None` for an unattested combination and raising on an undeclared feature or value. `IPAFeatures.build_segment` accepts feature bundles alongside base symbols, so the structured level is constructible from features too (#21).
- The `channel` axis (+z): where the airflow channel sits in cross-section — `lateral` → `flat` → `grooved`, out to in. It replaces the binary `lateral` and adds **sibilance**, which was unencoded: `s` and `θ` previously differed only by a tiny place step and scored near-identical, though they differ in tongue cross-section. Sibilants now group together (`s`~`ʃ` well below `s`~`θ`). `describe()` reports sibilants as such (#17).
- Data-integrity guards: typed features may carry no per-value tables, anchored features must be fully anchored (a partial anchor silently mixes tract-space and declaration-order distance), aliases must resolve, phone features must be declared (#17).
- `import_phoneset()`: explicit wild-import for phonesets; `distance_model(phoneset)`/`DistanceModel.for_phoneset` now warn — never silently drop — when phoneset members are absent from the matrix, with a specific hint when they are tie-convention spellings of known compounds. `from_wild` and `import_phoneset` exposed at module level (#15).
- `docs/distance.md`: the phonetic distance model — what a segment carries, why anchors rather than scale positions, the reference frame, how segments and bundles are compared, what is deliberately not weighted, and what the numbers mean for calibration (#17).
- Segments carry their **active articulator** (the organ that makes the constriction: lower lip, tongue tip/blade/front/dorsum/root, epiglottis, vocal folds), declared per place value and overridden per phone where it differs — place names the target, not the mover. Linguolabials (`t̼`: tongue tip at a labial target) and apical/laminal contrasts (`t̺`/`t̻`) were previously invisible to the metric; a combining place combines its articulators (`w` moves lower lip *and* dorsum). `articulator` is re-typed categorical over the real organ inventory. Design note for the full gestural model this points at: `docs/gestural-model.md` (#17).
- A coherent reference frame for the ordinal scales, declared in the data (`axis` per feature): `place`/`backness` share +x (lips→glottis), `height` flips to ascend +y (open→close; metrically free), `tone` +y, `manner` +constriction, `phonation` ascends glottal aperture. `silence` is off-scale (equidistant from every manner); `release`/`airstream` are categorical. Combining value names (`bilabial^velar`, ordered by scale position, friendly names as aliases) replace the mutated forms and the last hardcoded place table — any same-manner fusion combines generatively (`p͡t` → `bilabial^alveolar`). Phones carry normalized tract coordinates (`arc` along the midline, `offset` for constriction; anchors hand-placed from anatomy in `ipa.xml`), and the sagittal bridge terms use that geometry to give cross-class spatial proximity (`j`~`i`, `w`~`u`, `k`~`u`) — previously a stop scored closer to /i/ than its own glide. Head shapes (`data/heads.xml`: adult-male, adult-female, child) project tract space to 2D for rendering and never affect distance. Silence (`␣`) receives no articulatory defaults and no tract position: it is exactly 1.0 from every speech sound (substituting it costs what deleting costs) instead of ~0.22. `confusion.json` regenerated (#17).
- `Segment.disagreements()`: the features whose values differ across a unit's constituents — a diagnostic read (composition reports, never referees; `t͡ɮ` stays legal). Structural marks (the linking `‿`, breaks `|`/`‖`) now tokenize as their own boundary tokens instead of gluing onto the preceding segment, and are transparent to word-level distance (`word_distance("lez‿ami", "lezami") = 0`) (#14).
- Structural distance (`ipakit.metric`): constituent-bundle alignment with kind-driven ordering (double articulation unordered, phased units and sequences ordered), a binding-sense term (`D(u͡i, u͜i) = 1/3`), weighted secondary-articulation place components (`tʲ` strictly between `t` and `c`), nasality/laterality bridge features, and combined-place expansion for atomic `w`/`ɥ`. `distance`/`segment_distance`/`Segment.distance` all route through it; `Feature.value_distance` accepts value tuples. Distances shift: affricates now cluster with affricates rather than with their bare components; `confusion.json` regenerated (#13).
- `from_wild()`: explicit import of IPA written in other tie conventions — glyph-variant spellings of registered compounds canonicalize (`t͜s` → `t͡s`, `a͡ɪ` → `a͜ɪ`); unregistered uniform-glyph chains get the sense heuristic; mixed-glyph (house-authored) chains pass through (#11).
- Registered phones: the lateral affricates `t͡ɬ` (aliases `t͜ɬ`, NAPA `ƛ`) and `d͡ɮ`, and the labial-velar plosives/nasal `k͡p`, `ɡ͡b`, `ŋ͡m` (#7).
- Typed ties as house convention (see `docs/ties.md`): the over-tie fuses constituents into one timing slot, the under-tie binds a sequence into one unit, and the over-tie binds tighter in mixed chains (#9).
- Structured segment API: `Segment`/`Constituent`/`Sense`/`Kind`, `parse_segment`/`parse_segments`, `IPAFeatures.segment`/`segments`/`build_segment` — flat chain stored, grouping/kind/bag/scalar derived; versioned JSON round trip; sense-correct (documented-lossy) IPA emission (#10).
- Unicode canonicalization at ingest: precomposed and decomposed input parse identically; tokens emit in NFC (#8).
- Drift guard: registered tie-barred entries must match composition, with pinned exceptions (#8).
- `DistanceModel.confusability`/`distance`/`nearest` fall back to feature-derived similarity for out-of-matrix phones (#8).

### Removed
- **Breaking.** The `to_ipa` alias: it did CMU-only conversion under a name that reads "anything → IPA", inviting false symmetry with `xsampa_to_ipa`/`from_kirshenbaum`. Use `from_cmu`, which names its source format as its siblings do. (The name is freed for a segments→string function.) `compose_single` is removed — it returned `{}` for anything that was not exactly one segment, another silent sentinel; `segment(s).scalar()` covers it. `wiki`/`wiki_ref`/`wiki_refs` and `features_to_shorts`/`shorts_to_features` are no longer exported at module level (still available on `IPAFeatures`): reference-URL lookup and short-name conversion are not the computation surface, and the short-name query language is already accepted directly by `phones_matching` (#20).

### Changed
- **Breaking.** Soft reads move behind `from_wild`, out of the default parse path. Lookalike substitution used to run inside `expand_ligatures`, so every entry point silently rewrote its input: `tokenize("kæt!")` returned `['k', 'æ', 't', 'ǃ']` — a sentence-final exclamation mark reborn as a voiceless alveolar click — `is_valid_ipa("kæt!")` said yes, and the round trip changed the string with no diagnostic. Default parsing is now strict house style: `g`, `:`, `?`, `'` and `!` are read literally, reported as unknown symbols by `validate_ipa` (with a note naming the reading `from_wild` would give them), and never substituted. `from_wild` applies the soft reads, alongside the tie canonicalization it already did; `normalize_lookalikes` remains public as the substitution on its own. The `ipakit features` CLI still soft-reads by default — it is an interactive lookup, and `--no-lookalikes` turns it off.
- **Breaking, data.** Two entries in the soft-read table were judgement calls and are now decided and documented (docs/ties.md). `'` reads as **primary stress** `ˈ` (U+02C8), not the ejective `ʼ` (U+02BC): ASCII conventions agree that a bare apostrophe marks stress — this package's own `kirshenbaum.xml` already maps `'` → `ˈ`, and X-SAMPA spells the ejective `_>` — and anyone writing an ejective has already reached for a modifier letter. `!` is removed from the table entirely: the alveolar click `ǃ`, downstep `ꜜ` (registered here, and what X-SAMPA and Africanist tone notation mean by `!`) and ordinary punctuation are all live readings, none dominates, and guessing is what produced the defect above. `!` therefore stays unknown even inside `from_wild`; `validate_ipa` names both candidates.
- Unknown characters no longer vanish quietly. `parse`/`tokenize`/`segmented`/`segments`/`segment` gain the same `strict=` policy the converters carry: `strict=True` raises `ValueError` naming what could not be parsed, and the default path — still total, because `distance` legitimately wants a number for out-of-vocabulary input — now warns instead of dropping in silence. `to_ipa(segments(x, strict=True)) == x` is a guarantee; without `strict` a stray character is at least audible. Registered separators (`.`, `#`) and whitespace are no longer miscounted as unknown symbols, which also fixes `word_distance("kæ.t", "kæt")` raising `ValueError` on a syllable break the tokenizer handles everywhere else.
- **Breaking, data.** The value combiner is `^`, not `+`: combining values are spelled `bilabial^velar`, `alveolar^palatal`, and generated combinations follow (`p͡t` → `bilabial^alveolar`). `+` is the positive value of every binary feature, so one glyph was doing both jobs: `expand("+")` returned two empty components, and `_value_index` dropped `+` from its own binary scale. Friendly aliases (`labial-velar`, `labial-palatal`) are unaffected and remain the readable spelling. No distance changes — `confusion.json` is unchanged.
- **Breaking, naming.** `segment` now names the `Segment` concept everywhere: `segment()` returns one `Segment` and `segments()` a list (formerly `parse_segment`/`parse_segments`); the old string-returning `segment()` is now `segmented()`. `IPAFeatures` methods take the module vocabulary — `tokenize`, `normalize`, `add_ties`, `segmented` (formerly `tokenize_ipa`, `normalize_ipa`, `add_tie_bars`, `segment_ipa`). `WordDistanceResult.distance` is renamed `edit_cost`, because it is a summed alignment cost and is *not* bounded to [0, 1] like the two other quantities that shared the word; `.distance` remains as a deprecated alias. `get_features` deliberately keeps its name: `IPAFeatures.features` is the feature-*definitions* inventory, a different thing (#19).
- Anchored dimensions (`place`, `backness`, `manner`, `height`) compute value distance from tract anchors rather than scale index: steps follow anatomy (`bilabial→labiodental` 0.03 vs `velar→uvular` 0.11), place and backness are commensurable, and distances no longer shift when a value is added to the inventory. Unanchored dimensions keep index distance (#17).
- Clicks are corrected: they carry `airstream="velaric"` (they were silently defaulting to pulmonic) and their real oral manner, so `click` leaves the manner scale. Previously a bilabial click and a bilabial plosive were indistinguishable to the metric — literally distance 0 under anchored place. Click accompaniment is now classified by airstream (#17).
- Ordinal scales carry only true points on their continuum: combined place values (`labial-velar`, `labial-palatal`) are declared with `expands` in the data, hold no ordinal position (`palatal→velar` is one step, not two), and compare by expansion; the metric's place-expansion table is now data-driven. `confusion.json` regenerated (#16).
- House style is strict: diphthong canonical spellings flip to the under-tie (`a͜ɪ`, `e͜ɪ`, …), the glyph is authoritative at every entry point (no cross-glyph aliases; `t͜s` is a sequential chain, `a͡ɪ` a fused overlay), emission is faithful (`parse(emit(x)) = x`; the collision list is gone), and reverse phoneset conversions canonicalize through `from_wild` so registered compounds round-trip with correct sense (#11).
- The redundant `a͡ʊ̯` registration is dropped: composition resolves the narrow-transcription variant identically on the fly (#11).
- Tied inventory entries are constituent-derived: `ipa.xml` keeps only spelling/aliases/href for them, the loader derives their features under each entry's sense, and `IPAFeatures.derived_phones` lists them — registered and computed features cannot drift (#10).
- Alias spellings resolve token-locally at every entry point; `get_features`/`get_phone`/`in` now resolve aliases (previously returned empty for e.g. `t͜s`) (#9).
- Unregistered under-tie chains keep their tie through tokenization and project their first element (previously rewritten to the over-tie and merged) (#9).
- Phoneset conversions (X-SAMPA, CMU, TIMIT, Kirshenbaum) project the under-tie onto the over-tie at the boundary: unit-hood survives, tie sense does not; round trips return canonical over-tie spellings (#9).
- `normalize_ipa` inserts the tie by sense: adjacent vowels bind sequentially, anything else fuses (#9).
- The spacing undertie `‿` is the IPA linking mark (feature renamed from `liaison`); tie bars carry their sense in the data (`tie=simultaneous`/`sequential`) (#9).
- Structural features no longer default onto phone bundles; `confusion.json` regenerated (distances shift in the third decimal) (#9).
- `_COARTICULATED_PLACES` trimmed to the two true double articulations (#7).
- `MAX_MATCH_LEN` raised from 6 to 11 so longer tie chains tokenize as one unit (#10).

### Fixed
- A secondary articulation was read off the glyph stack rather than off the assembled bundle, so it registered only when it was written as a modifier: `ɫ`, which carries `velarized` as a base feature, compared as plain `l` (`distance("l", "ɫ") = 0.0`, `confusability = 1.0`, `word_similarity("fiːl", "fiːɫ") = 1.0`, and `describe` gave both the same name) — the metric dropped the property key on the premise that its content came back as a weighted place component, and for `ɫ` that component was never added. The mapping is now keyed by feature, so the articulation counts exactly once however it is spelled: the three spellings of dark l (`ɫ`, `lˠ`, `l̴`) are at distance 0 from each other, `distance("l", "ɫ") = distance("l", "lˠ")`, and the diacritics that had no glyph entry at all (`◌̴` velarized, `ᶣ` labio-palatized) register too. `tʲ` stays strictly between `t` and `c` — the articulation is not double-charged. `describe` renders secondary articulation ahead of the primary place, as the conventional names do (`ɫ` → `voiced velarized lateral alveolar approximant`). `confusion.json` regenerated: 95 of 9591 pairs move, all of them `ɫ` pairs, by at most 0.0069.
- The X-SAMPA round-trip guarantee in the README was not true: it enumerated three exceptions (`b͡v`, `t͡θ`, `ŋ͡m`) and reality had nine. Nine IPA symbols converted to the empty string and were deleted mid-word, taking their neighbours' adjacency with them (`ipa_to_xsampa("kⱱt") == "kt"`) — the labiodental flap `ⱱ`, the lowering diacritic `̞`, the redundant spellings `˞`/`̀`/`́`/`̄`/`ʻ`, and `ˀ`/`ᵊ`. The lowered diacritic was a plain oversight and is now mapped (`_o`, the counterpart of the `̝` → `_r` already shipped); the other eight are documented, each with its reason, and are named by `strict=True`. `ⱱ` is left unmapped deliberately: X-SAMPA predates the IPA's 2005 adoption of the symbol and has never assigned one (the standard chart marks that cell as having none), so any spelling would be invention that collides with notation already in use — Kirshenbaum has no notation for it either. A new test sweeps the whole inventory and asserts the round-trip failure set *equals* the documented list, so the claim and the code cannot drift apart again; the generator now refuses to emit a table with an undeclared gap in it, which is how these vanished unnoticed in the first place.
- Combining feature values answered malformed spellings instead of refusing them: `expand("")` was `("",)`, `expand("a^^b")` was `("a", "", "b")`, and `combine(set())` manufactured `""` — a typo or a half-built value came back as a plausible mid-range distance computed from a phantom component. `Feature.expand` now raises `ValueError` on a structurally malformed spelling (any empty component: `""`, `"^"`, `"a^"`, `"a^^b"`), and `Feature.combine` raises on no values at all or on a malformed member. It stays generative: an undeclared but well-formed component (`bilabial^NOTAPLACE`) still expands and still compares at maximal distance, exactly as an undeclared plain value does — declaration is a question about the data, an empty component is not a value under any data. `expand` also resolves value aliases per component rather than only on the whole spelling, so `labial-velar^palatal` expands to declared components, and `combine` expands its members first so it can no longer emit a spelling (`alveolar^labial-velar`) that `expand` was unable to normalize. No distance changes — `confusion.json` is unchanged.
- `features()` returned `{}` for any base carrying a diacritic — `tʲ`, `ã`, `tʰ`, `eː`, `n̩`, ordinary transcription — the same answer it gives for input that is not IPA at all. The structured level read those strings correctly the whole time, so the two levels disagreed about the same string (254 of 256 sampled base+diacritic units; now 0). The flat read now routes through the same parse the structured level uses, and refuses a parse that silently discarded input (`q͡X` is not `q`). Downstream, `describe()` no longer reports `unknown phone`, `minimal_pairs`/`nearest_phones` resolve, and `natural_class(["tʲ", "t"])` no longer drops the member it could not read and then assert `palatalized: '-'` of both. `IPAFeatures.__contains__` tracks what `get_features` resolves, as it documents. Prosodic marks remain the documented exception: they belong to the unit, not its feature bag, so `eː` reads the features of `e` and carries `ː` as prosody.
- `describe` read no modifier feature out on a vowel: the vowel branch returned after height, backness and rounding, so `nasalized`, `retroflex`, `syllabic` and the secondary articulations were all invisible on that half of the inventory — `describe("ã")` was `open front unrounded vowel`, the same name as plain `a`, though the metric puts them 0.048 apart. Nasalized vowels are ordinary transcription, so this was the higher-traffic instance of the `l`/`ɫ` defect above. Both classes now read their modifiers out ahead of the primary articulation, as the conventional names do: `ã` is a `nasalized open front unrounded vowel` and `ɚ` an `r-colored mid central unrounded vowel` (a vowel's retroflexion is named for its acoustic effect, matching those phones' own reference). `channel` stays consonant-only — it names where the airflow channel sits within a constriction, and a vowel has none — and voicing stays off vowels, since no vowel letter declares it and reading it out would call every one of them voiceless. `syllabic` is read out on consonants, which resolves `l` against `l̩`. No distance changes: `confusion.json` is unchanged.
- `distance()` returned the maximal-difference sentinel `1.0` for any multi-unit input, so two identical words reported as maximally different with no error. It now raises and names `word_distance`/`segment_distance`, both of which are exported alongside `pairwise_distances` (#18).
- A query whose terms all failed to resolve returned the **entire inventory** (a vacuous `all()`), so a typo silently matched everything. It now raises (#18).
- `word_distance`/`word_similarity` silently dropped symbols the tokenizer could not convert, measuring over the remainder — `"kæt"` against `"k4t"` compared `kæt` to `kt`. Measurement is now strict by default; `strict=False` opts back into lossy behaviour. Conversion keeps its lossy default (#18).
- Phone feature bundles are read-only: the module API is backed by one cached instance, so a write through `get_phone(...).features` corrupted the inventory every later call read (#18).
- `nearest_phones` returned `[]` for unregistered composable units while `describe`/`distance` accepted them, and `[]` for unresolvable input, where an empty list reads as "no neighbours" rather than "unsupported". It now accepts any resolvable unit and raises otherwise (#18).
- Precomposed characters (`ã`) were silently dropped at ingest; decomposed `ç` misparsed as bare `c` (#8).
- The under-tie was dropped entirely at X-SAMPA conversion, degrading registered units to clusters (#9).
- `validate_ipa` treats both ties as ties; a lone under-tie is malformed, not standalone (#9).
