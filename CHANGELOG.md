# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Entries that change existing behaviour are marked **Breaking**; those that change the shipped data are marked **Breaking, data**.

### Added
- Structured segment API: `Segment`/`Constituent`/`Sense`/`Kind` and `segment()`/`segments()`/`build_segment()` — the flat chain is stored, and grouping, kind, `bag()`, `scalar()` and `disagreements()` are derived; versioned JSON round trip; sense-correct (documented-lossy) IPA emission. `disagreements()` names the features whose values differ across a unit's constituents — a diagnostic read, because composition reports and never referees, so `t͡ɮ` stays legal (#10).
- `find(ipa, query)`: natural-class search over a transcription — the query language `phones_matching` runs over the inventory, run over the units of a string instead (one resolver, shared, rather than a second dialect). Matches are `(index, Segment)` pairs indexed against `segments()`, so the unit's structure is in hand and `to_ipa()` spells it, and an unresolvable query raises here as it does there instead of reporting every unit. `to_ipa(units)` joins structured units back into one string — the inverse of `segments()`, documented as no stronger than `Segment.to_ipa`: legacy alias spellings come back canonical, and marks belonging to no unit are carried by no Segment. `feature_values(unit)` names the bridge from the flat API to the structured reads — the multi-valued companion of `features()`, which is the scalar one (#22).
- The feature level is writable, not just readable: `to_phone(bundle)` realizes a feature bundle as the registered symbol that names it (the inverse of `features()` — exact on the keys given, free on the keys omitted, ties resolved by fewest declared extras, then fewest constituents, then declaration order), and `respell(phone, **changes)` applies a feature delta and realizes the result (`respell("t", voiced="+")` → `d`, `respell("p", place="velar")` → `k`). `to_phone` returns `None` for an unattested combination, raises on an undeclared feature or value and on an empty bundle — every phone satisfies a bundle that asks nothing, so an answer there would be a sentinel, and silence stays reachable by asking for it (`to_phone({"manner": "silence"})`) — and resolves value aliases through the same table as every other entry point, so `{"place": "labial-velar"}` is a query rather than a silent `None`. `IPAFeatures.build_segment` accepts feature bundles alongside base symbols, so the structured level is constructible from features too (#21).
- Structural distance (`ipakit.metric`): constituent-bundle alignment with kind-driven ordering (double articulation unordered, phased units and sequences ordered), a binding-sense term (`D(u͡i, u͜i) = 1/3`), weighted secondary-articulation place components (`tʲ` strictly between `t` and `c`), nasality/laterality bridge features, and combined-place expansion for atomic `w`/`ɥ`. `distance`/`segment_distance`/`Segment.distance` all route through it; `Feature.value_distance` accepts value tuples. Distances shift: affricates now cluster with affricates rather than with their bare components; `confusion.json` regenerated (#13).
- `ipakit.closure.MetricClosure` supplies a metric view of the distance for callers that need the triangle inequality — the shortest-path closure over an inventory, satisfying the inequality by construction. It is deliberately not exported at module level and not the default: closure shortens a pair whenever a third phone offers a cheaper path, and over the shipped inventory those paths are mostly artifacts (a double articulation shares one constituent with each endpoint, so `ɡ → ɡ͡b → b͡v` is cheap while a voiced velar plosive and a voiced labiodental affricate are not alike). About a fifth of pairs shorten and the largest shortcuts join some of the least similar pairs, so `shortened()` reports exactly what a closure cost you, and a pair outside the inventory raises rather than falling back to the open distance.
- The `channel` axis (+z): where the airflow channel sits in cross-section — `lateral` → `flat` → `grooved`, out to in. It replaces the binary `lateral` and adds **sibilance**, which was unencoded: `s` and `θ` previously differed only by a tiny place step and scored near-identical, though they differ in tongue cross-section. Sibilants now group together (`s`~`ʃ` well below `s`~`θ`) (#17).
- Segments carry their **active articulator** (the organ that makes the constriction: lower lip, tongue tip/blade/front/dorsum/root, epiglottis, vocal folds), declared per place value and overridden per phone where it differs — place names the target, not the mover. Linguolabials (`t̼`: tongue tip at a labial target) and apical/laminal contrasts (`t̺`/`t̻`) were previously invisible to the metric; a combining place combines its articulators (`w` moves lower lip *and* dorsum). `articulator` is re-typed categorical over the real organ inventory. Design note for the full gestural model this points at: `docs/gestural-model.md` (#17).
- A coherent reference frame for the ordinal scales, declared in the data (`axis` per feature): `place`/`backness` share +x (lips→glottis), `height` flips to ascend +y (open→close; metrically free), `tone` +y, `manner` +constriction, `phonation` ascends glottal aperture. `silence` is off-scale (equidistant from every manner); `release`/`airstream` are categorical. Phones carry normalized tract coordinates (`arc` along the midline, `offset` for constriction; anchors hand-placed from anatomy in `ipa.xml`), and the sagittal bridge terms use that geometry to give cross-class spatial proximity (`j`~`i`, `w`~`u`, `k`~`u`) — previously a stop scored closer to /i/ than its own glide. Head shapes (`data/heads.xml`: adult-male, adult-female, child) project tract space to 2D for rendering and never affect distance. Silence (`␣`) receives no articulatory defaults and no tract position: it is exactly 1.0 from every speech sound, so substituting it costs what deleting costs. `confusion.json` regenerated (#17).
- `from_wild()`: explicit import of IPA written in other tie conventions — glyph-variant spellings of registered compounds canonicalize (`t͜s` → `t͡s`, `a͡ɪ` → `a͜ɪ`), unregistered uniform-glyph chains get the sense heuristic, and mixed-glyph (house-authored) chains pass through. `import_phoneset()` is the same explicit wild-import for phonesets; `distance_model(phoneset)`/`DistanceModel.for_phoneset` now warn — never silently drop — when phoneset members are absent from the matrix, with a specific hint when they are tie-convention spellings of known compounds. Both are exposed at module level (#11, #15).
- Registered phones: the lateral affricates `t͡ɬ` (aliases `t͜ɬ`, NAPA `ƛ`) and `d͡ɮ`, and the labial-velar plosives/nasal `k͡p`, `ɡ͡b`, `ŋ͡m` (#7).
- Typed ties as house convention (see `docs/ties.md`): the over-tie fuses constituents into one timing slot, the under-tie binds a sequence into one unit, and the over-tie binds tighter in mixed chains. The spacing undertie `‿` is the IPA linking mark (the feature is renamed from `liaison`), and tie bars carry their sense in the data (`tie=simultaneous`/`sequential`). The linking mark and the breaks `|`/`‖` tokenize as their own boundary tokens instead of gluing onto the preceding segment, and are transparent to word-level distance (`word_distance("lez‿ami", "lezami") = 0`) (#9, #14).
- Unicode canonicalization at ingest: precomposed and decomposed input parse identically, and tokens emit in NFC. Recomposition looks across a base's whole run of combining marks, so canonical reordering cannot strand a symbol's own mark — applying an overlay to `ç` reorders it ahead of the cedilla (ccc 1 before ccc 202), and `ç̴` keeps its cedilla instead of reading as `c̴` (#8).
- `DistanceModel.confusability`/`distance`/`nearest` fall back to feature-derived similarity for out-of-matrix phones (#8).
- `docs/distance.md`: the phonetic distance model — what a segment carries, why anchors rather than scale positions, the reference frame, how segments and bundles are compared, what is deliberately not weighted, and what the numbers mean for calibration (#17).
- `docs/reviewing.md`: how defects in this library have actually been found. Thirty-three were fixed across six review rounds and **every one was a silent wrong answer under a green suite** — none was a crash — so the document is about producing evidence rather than forming opinions: measure the matrix before and after and explain every mover, sweep generated input rather than naming cases (and assert the corpus size so a sweep cannot go vacuous), write a guard as a predicate over the *shape* of the mistake, prefer making two things equal by construction over vigilance, pin what a guard cannot see, and check whether the data is wrong before making the code clever.
- `scripts/invariants.py`: one command for the properties the library is supposed to hold — identity, symmetry, range, no distinct pair at distance 0, both round trips, the three flat reads agreeing, description uniqueness, and derived artifacts current. Exits non-zero, so it gates a release; `--quick` skips the O(n²) sweeps. Verified to bite by reintroducing the `l`/`ɫ` defect below, which it reports as `d(l,ɫ)=0 but they are different phones`. Alongside it, load-time data-integrity guards: typed features may carry no per-value tables, anchored features must be fully anchored (a partial anchor silently mixes tract-space and declaration-order distance), aliases must resolve, phone features must be declared, every non-obstruent speech phone must declare its voicing, and registered tie-barred entries must match composition, with pinned exceptions (#8, #17).

### Removed
- **Breaking.** The `to_ipa` alias: it did CMU-only conversion under a name that reads "anything → IPA", inviting false symmetry with `xsampa_to_ipa`/`from_kirshenbaum`. Use `from_cmu`, which names its source format as its siblings do. (The name is freed for a segments→string function.) `compose_single` is removed — it returned `{}` for anything that was not exactly one segment, another silent sentinel; `segment(s).scalar()` covers it. `wiki`/`wiki_ref`/`wiki_refs` and `features_to_shorts`/`shorts_to_features` are no longer exported at module level (still available on `IPAFeatures`): reference-URL lookup and short-name conversion are not the computation surface, and the short-name query language is already accepted directly by `phones_matching` (#20).

### Changed
- **Breaking, naming.** `segment` now names the `Segment` concept everywhere: `segment()` returns one `Segment` and `segments()` a list (formerly `parse_segment`/`parse_segments`); the old string-returning `segment()` is now `segmented()`. `IPAFeatures` methods take the module vocabulary — `tokenize`, `normalize`, `add_ties`, `segmented` (formerly `tokenize_ipa`, `normalize_ipa`, `add_tie_bars`, `segment_ipa`). `WordDistanceResult.distance` is renamed `edit_cost`, because it is a summed alignment cost and is *not* bounded to [0, 1] like the two other quantities that shared the word; `.distance` remains as a deprecated alias. `get_features` deliberately keeps its name: `IPAFeatures.features` is the feature-*definitions* inventory, a different thing (#19).
- **Breaking.** Soft reads move behind `from_wild`, out of the default parse path, and the two entries in the soft-read table that were judgement calls are now decided and documented (docs/ties.md). Lookalike substitution used to run inside `expand_ligatures`, so every entry point silently rewrote its input: `tokenize("kæt!")` returned `['k', 'æ', 't', 'ǃ']` — a sentence-final exclamation mark reborn as a voiceless alveolar click — `is_valid_ipa("kæt!")` said yes, and the round trip changed the string with no diagnostic. Default parsing is now strict house style: `g`, `:`, `?`, `'` and `!` are read literally, reported as unknown symbols by `validate_ipa` (with a note naming the reading `from_wild` would give them), and never substituted; `from_wild` applies the soft reads alongside the tie canonicalization it already did, `normalize_lookalikes` remains public as the substitution on its own, and the `ipakit features` CLI still soft-reads by default because it is an interactive lookup (`--no-lookalikes` turns it off). Of the two judgement calls, `'` reads as **primary stress** `ˈ` (U+02C8), not the ejective `ʼ` (U+02BC) — ASCII conventions agree that a bare apostrophe marks stress, this package's own `kirshenbaum.xml` already maps `'` → `ˈ`, X-SAMPA spells the ejective `_>`, and anyone writing an ejective has already reached for a modifier letter — and `!` is removed from the table entirely, because the alveolar click `ǃ`, downstep `ꜜ` (registered here, and what X-SAMPA and Africanist tone notation mean by `!`) and ordinary punctuation are all live readings, none dominates, and guessing is what produced the defect above. `!` therefore stays unknown even inside `from_wild`; `validate_ipa` names both candidates.
- **Breaking.** Unknown characters no longer vanish quietly. `parse`/`tokenize`/`segmented`/`segments`/`segment` gain the same `strict=` policy the converters carry: `strict=True` raises `ValueError` naming what could not be parsed, and the default path — still total, because `distance` legitimately wants a number for out-of-vocabulary input — now warns instead of dropping in silence. `to_ipa(segments(x, strict=True)) == x` is a guarantee; without `strict` a stray character is at least audible. Registered separators (`.`, `#`) and whitespace are no longer miscounted as unknown symbols.
- **Breaking, data.** House style is strict: diphthong canonical spellings flip to the under-tie (`a͜ɪ`, `e͜ɪ`, …), the glyph is authoritative at every entry point (no cross-glyph aliases; `t͜s` is a sequential chain, `a͡ɪ` a fused overlay), emission is faithful (`parse(emit(x)) = x`; the collision list is gone), and reverse phoneset conversions canonicalize through `from_wild` so registered compounds round-trip with correct sense. `normalize_ipa` inserts the tie by sense — adjacent vowels bind sequentially, anything else fuses. Unregistered under-tie chains keep their tie through tokenization and project their first element (previously rewritten to the over-tie and merged), the redundant `a͡ʊ̯` registration is dropped because composition resolves the narrow-transcription variant identically on the fly, and `MAX_MATCH_LEN` is raised from 6 to 11 so longer tie chains tokenize as one unit (#9, #10, #11).
- **Breaking, data.** Combining values are spelled with `^`, not `+`: `bilabial^velar`, `alveolar^palatal`, and generated combinations follow (`p͡t` → `bilabial^alveolar`), so `features("w")["place"]` is `bilabial^velar`. `+` is the positive value of every binary feature, so one glyph was doing both jobs: `expand("+")` returned two empty components, and `_value_index` dropped `+` from its own binary scale. The friendly aliases (`labial-velar`, `labial-palatal`) are unaffected, remain the readable spelling, are accepted anywhere a value is taken, and are what a description prints — `w` is a `labial-velar approximant`, not a `bilabial^velar` one. Combined values are declared with `expands` in the data and carry only true points on their continuum: they hold no ordinal position (`palatal→velar` is one step, not two) and compare by expansion, so the metric's place-expansion table is data-driven and any same-manner fusion combines generatively. `confusion.json` regenerated (#16, #17).
- **Breaking, data.** Pre-glottalization `ˀ` and the schwa release `ᵊ` are declared for what they are: `release="glottal"` and `release="schwa"`, two new values of the existing `release` feature. They previously declared `manner="plosive" place="glottal"` and `height="mid" backness="central"` — the features of the sounds they are *named after*, not the contribution they make — and the misdeclaration leaked into every bundle whose base was of the complementary class: over the 139 phones × {plain, `ˀ`, `ᵊ`}, 32 units carried a bogus `place="glottal"` (a vowel with a place of articulation — `aˀ`, `eˀ`, …, and `␣ˀ`) and 100 carried a bogus `height="mid" backness="central"` (a consonant with a vowel quality — `tᵊ`, `sᵊ`, …). Those keys are gone and the 262 marked units now carry `release` instead; the `_MODE_EXCEPTIONS` table that existed to paper over it is deleted, because the existing `"release" in keys` rule now classifies both marks from the data alone. `to_phone` changes for 130 units, from the bare base symbol to `None` — nothing registered spells "alveolar plosive with a glottal release", which is the same answer `to_phone(features("tʰ"))` has always given, and the old answer only arose because the mark contributed nothing at all. The shipped `confusion.json` is unchanged to 1e-12 across all 9,591 pairs, because no registered phone spells either mark or carries a `release` feature; distances involving the marks do move — 70,897 of the 86,736 pairs over the extended 417-unit set, max |Δ| 0.300 (`␣ˀ`~`␣ᵊ`, 0.8 → 0.5), mean |Δ| 0.026 — and every mover has at least one side whose constituent bundle changed.
- The tables that stated phonetic facts in Python are declared in `ipa.xml` and derived from it. A feature declares the contribution mode it implies (`<feature name="velarized" mode="secondary" place="velar">`, against a `<modes>` vocabulary whose declaration order is precedence), so `ipakit.segment`'s four key sets and `ipakit.metric`'s `SECONDARY_PLACE` collapse into one statement read several ways — the secondary-articulation *set* and the secondary→place *table* were previously three independent copies in three modules, agreeing only by habit. Manner values declare their natural class (`natural-class="obstruent"`), replacing `_ORAL_OBSTRUENT`. Values declare how a description reads them (`<value name="grooved" label="sibilant"/>`, `<value name="-" label="voiceless"/>`), replacing `_BINARY_LABELS`; features declare which manner classes read them out (`applies="consonant"` on `channel` and `retroflex`, `applies="nucleus"` on `rhotacized`), so `_CONSONANT_MODIFIERS` and `_VOWEL_MODIFIERS` become two views of one declaration and only the read-out *order* stays in Python. A `<bridges>` block declares that one dimension can be spelled several ways (`nasality` = `manner=nasal` ∪ `nasalized=+` ∪ `release=nasal`), and the metric's exclusion list is derived from it rather than listed. `CMUMapper` no longer keeps its own `{"ˈ": 1, "ˌ": 2}` beside a comment saying the canonical inventory lives in the data. No behaviour changes: features, `describe`, `to_phone`, `kind` and distances are identical across 33,045 observations, and `confusion.json` is untouched. A guard holds the line: `tests/test_declared_not_hardcoded.py` walks every module with `ast` and rejects a module-level constant that enumerates two or more declared feature values, that classifies two or more declared feature names in an unordered container, or that uses a registered symbol as a dict key or set member. It is a predicate over the *shape* of the mistake rather than a list of today's names, and it is tested against the tables that were removed. It deliberately spares an ordered list of feature *names* (an order is not a classification): the one that survives, the description read-out order, is separately pinned so it can only order what the data already admits. A companion test pins the shapes that still escape it, so they stay known rather than assumed shut.
- Anchored dimensions (`place`, `backness`, `manner`, `height`) compute value distance from tract anchors rather than scale index: steps follow anatomy (`bilabial→labiodental` 0.03 vs `velar→uvular` 0.11), place and backness are commensurable, and distances no longer shift when a value is added to the inventory. Unanchored dimensions keep index distance (#17).
- Clicks are corrected: they carry `airstream="velaric"` (they were silently defaulting to pulmonic) and their real oral manner, so `click` leaves the manner scale. Previously a bilabial click and a bilabial plosive were indistinguishable to the metric — literally distance 0 under anchored place. Click accompaniment is now classified by airstream (#17).
- `_COARTICULATED_PLACES` trimmed to the two true double articulations (#7).
- Tied inventory entries are constituent-derived: `ipa.xml` keeps only spelling/aliases/href for them, the loader derives their features under each entry's sense, and `IPAFeatures.derived_phones` lists them — registered and computed features cannot drift (#10).
- Alias spellings resolve token-locally at every entry point; `get_features`/`get_phone`/`in` now resolve aliases (previously returned empty for e.g. `t͜s`) (#9).
- Phoneset conversions (X-SAMPA, CMU, TIMIT, Kirshenbaum) project the under-tie onto the over-tie at the boundary: unit-hood survives, tie sense does not; round trips return canonical over-tie spellings (#9).
- Structural features no longer default onto phone bundles; `confusion.json` regenerated (distances shift in the third decimal) (#9).

### Fixed
- The hardcoded-constant guard (`tests/test_declared_not_hardcoded.py`) saw only the syntax it was first written against, and missed nine shapes of the same mistake — including `_STRESS_MARKERS = ["ˈ", "ˌ"]`, the stress table its own docstring names as the worked example, which escaped merely for being a list rather than a set. It now reads a per-symbol table as a table in a container of any kind, ordered or not, and finds a constant however it is bound: unpacked from a tuple, nested in a module-level `if` or `try`, filled one subscript at a time, extended with `|=`, bound by a walrus, concatenated out of fragments, or joined into a single delimited string for the use site to `.split()` (any of `,;|/`, whitespace, or a separator the source itself names). The *classification* arm still spares an ordered sequence of feature names, because where a name goes in a sentence is a rendering decision and three legitimate ones exist. A string is read as a member list only when every piece of it is a declared term, so prose that happens to mention two of them stays prose — which also stops the guard reading `# fmt: off` as a symbol table. Twelve synthetic cases pin the newly-caught shapes and seven pin what still escapes (an ordered sequence of names, a constant inside a class or function, a fact spelled as an `if`/`elif` chain, an undelimited run of glyphs, indirection through another name, and an unguessable delimiter), and the docstring now states both lists. Test-only: no library behaviour changes and the matrix is untouched.
- **Breaking.** Ligature aliases (`ʦ ʧ ʤ ʣ ʥ ʨ ƛ ˖ ˗`) resolve everywhere an IPA string is read. They resolved in `tokenize` but not in `parse`, and the converters never called `parse` at all — they greedy-matched their own tables — so `to_cmu("ʧe͜ɪnd͡ʒ")` returned three phonemes where the canonical spelling of the same word returned four, `ipa_to_xsampa("ʧ")` was `''`, and `features("ʦʰ")` was `{}` while the structured read had it right. The library called the string valid and tokenized it correctly first, so the loss was silent. `parse` now expands ligatures, `_resolve_token` *is* `expand_ligatures` (its old whole-token lookup read `ʦ` but not `ʦʰ`), and the three converters share one `resolve_aliases`. An alias and its canonical are now one string at every entry point, checked by `scripts/invariants.py` over 7,956 readings.
- **Breaking.** A stress mark binds the unit that *follows* it wherever it stands, not only at the start of a string. It was collected as a trailing modifier of the preceding base, so it migrated left across a segment boundary: `ˌɪntəˈneɪʃənəl` re-emitted as `ˌɪntˈəneɪʃənəl`, putting primary stress on a different syllable, and the library's own `normalize_stress_to_nucleus` output bound the mark to an onset. Only stress moves rightward — length and tone are written after the segment they scope and still bind left. Two marks before one unit are a contradiction rather than a stack: the nearest binds and the superseded one is reported, warning by default and raising under `strict=True`, with `validate_ipa` naming `unbound_stress`/`superseded_stress` so parser and validator agree. No distances move; stress is prosody, which the metric excludes.
- `features()` returned `{}` for any base carrying a diacritic — `tʲ`, `ã`, `tʰ`, `eː`, `n̩`, ordinary transcription — the same answer it gives for input that is not IPA at all. The structured level read those strings correctly the whole time, so the two levels disagreed about the same string (254 of 256 sampled base+diacritic units; now 0). The flat read now routes through the same parse the structured level uses, and refuses a parse that silently discarded input (`q͡X` is not `q`). Downstream, `describe()` no longer reports `unknown phone`, and `minimal_pairs`/`nearest_phones` resolve. `IPAFeatures.__contains__` tracks what `get_features` resolves, as it documents. Prosodic marks remain the documented exception: they belong to the unit, not its feature bag, so `eː` reads the features of `e` and carries `ː` as prosody.
- **Breaking.** `features()`, `compose()` and `Segment.scalar()` are documented as one read of one unit and were three implementations of it; all three now route through one function, `ipakit.segment.flat_projection` — the left-to-right merge of the constituents' own bundles, with a sequential chain projecting its first block — and through one overlay, `ipakit.segment.apply_modifiers`. Three things were wrong at once. A diacritic was applied unconditionally on the flat side while `Constituent.bundle` had always applied it by mode (an overriding mark assigns; everything else adds what the base leaves unstated), so a release-phase mark spoke for the whole segment: `features("tˀ")["place"]` was `glottal` though the `t` is alveolar and `bag()` said so, `features("kᵊ")` gave a velar plosive a vowel height, and `features("ǀʼ")["airstream"]` was `ejective` where the click's own bag says `velaric` — over the 7,424 base+diacritic strings that parse to an atomic unit, 140 cells diverged (`place`/`ˀ` 81, `height`/`ᵊ` 29, `backness`/`ᵊ` 20, `airstream`/`ʼ` 10), and now none do. A diacritic's metadata was reported as the unit's: `features("tʰ")["href"]` was `Aspirated_consonant`, the article for the *mark*, where `href`/`xsampa`/`class` name a symbol and the symbol a unit's metadata describes is its base — 7,911 of 9,035 token bundles change on metadata alone, and a precomposed spelling registered in its own right (`ť`, the alveolar ejective) is a phone rather than an overlay and keeps its own article. And a mark on any constituent other than the last was dropped or applied out of order: `features("t̪͡s")["place"]` was `alveolar` where `segment("t̪͡s").scalar()` said `dental`, `features("n̥͡d")["voiced"]` was `+` where `scalar()` said `-`, `segment("kʷ͡p").scalar()["labialized"]` was `-` where `bag()` said `('+', '-')`, and `compose("a͜ɪ̃")` reported `nasalized=+` where a sequential chain projects its first block and the flat read says `-`. Over the 128,698 well-formed `base + mark + tie + base` strings the inventory can spell, in both mark positions, `get_features` and `scalar` disagreed on 25,036, `compose` and `get_features` on 21,725, `compose` and `scalar` on 3,311; all three now agree on all 128,698, and a sweep test holds it. The values that moved are `scalar`'s and `compose`'s: the flat read of `t̪͡s` is alveolar because an affricate takes the place of its release (which is why `t͡ʃ` is postalveolar), and a mark past the first under-tie block does not reach the projection at all — nothing is lost by that, since `bag()`, `feature_values()` and `disagreements()` carry every constituent's values as they always did, and `kʷ͡p` still reports `labialized='+'` because `p` states no labialization and the merge preserves what a later constituent leaves unstated. The overlay runs before the defaults are filled, because a mark that adds what the base leaves unstated (nasalization on a vowel) would otherwise find the default already in the slot. The registry wins only for a block spelled as a registered entry: inside a chain, `k͡p̪` was read as the registered `k͡p` wearing a dental mark — `place=dental` — because the greedy base match swallowed the whole ligature, where the structured parse binds the mark to the `p` it sits on and gives the double articulation `dental^velar`, so a tie-bearing block that is not itself registered now always merges its parts. The one documented divergence stays exactly one thing: `compose("eː")["length"]` is `long` where `scalar()` reports the length of `e` and carries the mark in `prosody`. 120 units change `describe` and `to_phone`, every one of them a `ˀ`/`ᵊ`/`ʼ` correction; no distances move, because the metric reads `Constituent.bundle` per constituent, which honoured each constituent's own marks all along, and the shipped `confusion.json` is bit-identical across all 9,591 pairs.
- `describe` now reports what a unit states, not only what its class expects. It read no modifier feature out on a vowel — the vowel branch returned after height, backness and rounding, so `nasalized`, `retroflex`, `syllabic` and the secondary articulations were all invisible on that half of the inventory, and `describe("ã")` was `open front unrounded vowel`, the same name as plain `a`, though the metric puts them 0.048 apart — and it was silent about release and phonation on the other half, so `tʰ`, `t̚`, `tˡ`, `tⁿ`, `tˀ`, `tᵊ`, `a̤` and `a̰` all described as their bare base. Both classes now read their modifiers out ahead of the primary articulation, as the conventional names do: `ã` is a `nasalized open front unrounded vowel`, `ɫ` a `voiced velarized lateral alveolar approximant`, `s` a `voiceless sibilant alveolar fricative`, and `ɚ` an `r-colored mid central unrounded vowel` (a vowel's retroflexion is named for its acoustic effect, matching those phones' own reference). Release and phonation declare display labels in the data, and a release is named **as a phase** — `tˀ` is a `voiceless glottalized alveolar plosive`, never a glottal one, and `aᵊ` keeps its own height and backness; `phonation=modal` and `phonation=devoiced` stay unsaid, the first because it is unremarkable and the second because it would repeat the voicing already read out. R-colouring is read on any nucleus rather than only on vowels: `rhotacized` declared `applies="vowel"`, so `ɹ̩˞` — the second syllable of American English *butter*, the commonest syllabic rhotic there is — read as `voiced syllabic alveolar approximant` while the identical sound spelled `ɚ` read as r-colored, though the colouring was in the bundle and in the metric all along. `rhotacized` now declares `applies="nucleus"`, a derived class meaning vowel-or-syllabic, because nucleus-hood is prosodic rather than a manner class — fricative and stop nuclei are attested (Tashlhiyt Berber, Miyako, Nuosu Yi), so it cannot be read off manner — and `feature_applies` takes the feature bundle rather than a bare manner, which is what makes the distinction expressible. Articulation features stay manner-based: `channel` names where a channel sits *within a constriction*, so a syllabic lateral keeps its "lateral" and a vowel never gains one. Finally, `applies` says where a feature is *expected*, not where it may be *reported*: a stated, non-default value is now always read out even where it falls outside the class its `applies` names, and `describe("ɡʴ")` no longer equals `describe("ɡ")` while the metric charges the difference — two distinct units under one name, the failure this path exists to prevent. Voicing stays unsaid on vowels, where it is unremarkable. No distances move — `confusion.json` is unchanged.
- **Breaking, data.** The data said every vowel was voiceless. `voiced` is binary with default `-`, which is the unmarked value for an obstruent and the wrong one for everything else, and no vowel declared it — every voiced consonant did, so vowels were simply omitted from the file's own convention. The metric took it literally, so a vowel spuriously *agreed* on voicing with every voiceless consonant and disagreed with every voiced one — at one point scoring /i/ nearer a voiceless nasal than a voiced one. This is the same shape as the clicks defaulting to a pulmonic airstream that `docs/distance.md` narrates. All 31 vowel entries now declare `voiced="+"` (the 8 derived diphthongs inherit it from their constituents), and `ʍ` — the one remaining non-obstruent reaching the default, correct only by accident — declares `voiced="-"`. A guard asserts every non-obstruent speech phone declares its voicing, so the default is only ever reached where it is right. 3861 of 9591 pairs move, max 0.0455, every mover involving a vowel, a vowel-derived unit, or `ʍ`; `confusion.json` regenerated.
- **Breaking, data.** R-colouring was spelled with two different features: `ɚ`/`ɝ` carried `retroflex` — declared *"Tongue tip curled back"*, `href` `Retroflex_consonant` — while the `˞` and `ʴ` diacritics that spell the same sound carried `rhotacized`. Same sound, two features, so the two spellings of an r-coloured schwa were not equal, and the two r-coloured vowels were the only `retroflex` phones that were not consonants (their own `href` says `R-colored_vowel`). They now carry `rhotacized`, so `d(ɚ, ə˞)` is 0.0 and the feature bundles are identical. `describe` names `rhotacized` "r-colored", after the feature's own description, and no longer needs a per-class label override. 16 pairs move, all of them `ɚ`/`ɝ` against retroflex consonants, which were spuriously close through a shared feature that meant two different things; `confusion.json` regenerated.
- A secondary articulation was read off the glyph stack rather than off the assembled bundle, so it registered only when it was written as a modifier: `ɫ`, which carries `velarized` as a base feature, compared and described as plain `l` — `describe` gave both the same name — because the metric dropped the property key on the premise that its content came back as a weighted place component, and for `ɫ` that component was never added. The mapping is now keyed by feature, so the articulation counts exactly once however it is spelled: the three spellings of dark l (`ɫ`, `lˠ`, `l̴`) are at distance 0 from each other, `distance("l", "ɫ") = distance("l", "lˠ")`, and the diacritics that had no glyph entry at all (`◌̴` velarized, `ᶣ` labio-palatized) register too. `tʲ` stays strictly between `t` and `c` — the articulation is not double-charged. `describe` renders secondary articulation ahead of the primary place, as the conventional names do (`ɫ` → `voiced velarized lateral alveolar approximant`). `confusion.json` regenerated: 95 of 9591 pairs move, all of them `ɫ` pairs, by at most 0.0069.
- A tie bar written *after* a diacritic was dropped, and dropped in silence: `tokenize("t̪͡s")` returned `['t̪', '͡', 's']` — a dental affricate reborn as a two-segment cluster — `segment("kʷ͡p")` raised `expected exactly one unit, got 2`, and `to_ipa(segments("t̪͡s", strict=True))` handed back `t̪s` with neither a warning nor a raise, though tie *presence* is contrastive by this project's own documentation and `strict=` exists precisely to make that round trip a guarantee rather than a hope. The tokenizer only spanned a tie between two *registered* bases, so a base carrying a modifier (`t̪`, `kʷ`, `ã`) ended the chain and the tie fell through to the standalone-diacritic branch; because the tie is itself a registered diacritic it never counted as an unknown symbol, so `strict=True` never saw the loss and the flat and structured levels contradicted each other on the same string. A tie now binds the whole preceding **unit** — base plus the modifiers written on it — across any number of constituents and either glyph: of the 13688 `<base><modifier><TIE><base>` combinations over the bundled inventory, 13684 were broken and 2 still are, both for an unrelated reason (a precomposed `ç` loses its cedilla to NFD mark reordering before the tie is ever reached). The control shape `<base><TIE><base><modifier>`, which always worked, is unchanged. A tie that binds nothing on one side is a dropped structural mark like any other: it warns by default and raises under `strict=True` instead of being emitted as a token and then discarded by the structured layer, and `validate_ipa`'s `malformed_tie` is widened from "tie at string boundary" to that same condition, so the validator and the parser agree on what is malformed — a tie after a break, after the linking mark, or after another tie is now reported (it was not), while a tie after a prosodic mark is not (it was), length and tone riding on the unit they follow exactly as the parser reads them. `validate_ipa` also treats both glyphs as ties, so a lone under-tie is malformed rather than standalone, and the under-tie is no longer dropped entirely at X-SAMPA conversion, where it had degraded registered units to clusters. No distance changes — `confusion.json` is bit-identical.
- The X-SAMPA round-trip guarantee in the README was not true: it enumerated three exceptions (`b͡v`, `t͡θ`, `ŋ͡m`) and reality had nine. Nine IPA symbols converted to the empty string and were deleted mid-word, taking their neighbours' adjacency with them (`ipa_to_xsampa("kⱱt") == "kt"`) — the labiodental flap `ⱱ`, the lowering diacritic `̞`, the redundant spellings `˞`/`̀`/`́`/`̄`/`ʻ`, and `ˀ`/`ᵊ`. The lowered diacritic was a plain oversight and is now mapped (`_o`, the counterpart of the `̝` → `_r` already shipped); the other eight are documented, each with its reason, and are named by `strict=True`. `ⱱ` is left unmapped deliberately: X-SAMPA predates the IPA's 2005 adoption of the symbol and has never assigned one (the standard chart marks that cell as having none), so any spelling would be invention that collides with notation already in use — Kirshenbaum has no notation for it either. A new test sweeps the whole inventory and asserts the round-trip failure set *equals* the documented list, so the claim and the code cannot drift apart again; the generator now refuses to emit a table with an undeclared gap in it, which is how these vanished unnoticed in the first place.
- The derived confusion matrix is now reproducible bit for bit. `bundle_distance` summed one float per feature key while iterating a *set* of key names, and float addition is not associative, so per-process string-hash randomization changed the summation order and with it the last bits of every distance — three runs under different `PYTHONHASHSEED` values produced three different matrices, differing in a few hundred of the 9591 pairs at ~1e-16. Only `dict` guarantees iteration order in Python; `set` never has. Keys are now sorted, which depends on nothing but the names themselves. `confusion.json` regenerated: 403 entries move by at most 2.2e-16, no phonetic change. A test runs the metric under four hash seeds in subprocesses and compares exact reprs.
- **Breaking.** Four reads answered where they should have failed. `distance()` returned the maximal-difference sentinel `1.0` for any multi-unit input, so two identical words reported as maximally different with no error; it now raises and names `word_distance`/`segment_distance`, both of which are exported alongside `pairwise_distances`. A query whose terms all failed to resolve returned the **entire inventory** (a vacuous `all()`), so a typo silently matched everything; it now raises. `nearest_phones` returned `[]` for unregistered composable units while `describe`/`distance` accepted them, and `[]` for unresolvable input, where an empty list reads as "no neighbours" rather than "unsupported"; it now accepts any resolvable unit and raises otherwise. `natural_class` filtered out the members it could not resolve and reported the shared features of the rest, so `natural_class(["tʲ", "t"])` asserted `palatalized: '-'` of both; it now raises and names the offending members, while an empty list and a genuinely-shared-nothing both keep their honest answers (#18).
- **Breaking.** `word_distance`/`word_similarity` silently dropped symbols the tokenizer could not convert, measuring over the remainder — `"kæt"` against `"k4t"` compared `kæt` to `kt`. Measurement is now strict by default; `strict=False` opts back into lossy behaviour. Conversion keeps its lossy default (#18).
- Phone feature bundles are read-only: the module API is backed by one cached instance, so a write through `get_phone(...).features` corrupted the inventory every later call read (#18).
- Precomposed characters (`ã`) were silently dropped at ingest; decomposed `ç` misparsed as bare `c` (#8).
- The documentation asserted things that were not true. `docs/distance.md` now states plainly that `distance` is **not a metric**: it is symmetric, zero on identity and bounded, but does not satisfy the triangle inequality (about 0.5% of triples over the shipped inventory violate it, some by a wide margin — a composite sits near two things that are far from each other, because it shares a different constituent with each). The section says which uses this rules out (metric trees, algorithms whose correctness rests on the inequality, naive Euclidean embedding) and which are unaffected (ranking, thresholding, alignment scoring), and a test keeps the claim honest in both directions. The CLI `--help` text and the module docstring quoted specific distance values that had all gone stale — the mechanism being that API docstrings use `>>>` and are pinned by `--doctest-modules`, while help text writes expected output as a `#` comment that nothing executes — so the fossilized numbers are gone (the qualitative note stays), and the stale symbolic examples are corrected: `describe t͡ʃ` missing "sibilant", `query match plosive bilabial` missing `ʘ`, three wrong `minimal-pairs` outputs. The README no longer quotes a specific `distance("p", "b")` value either, in the very paragraph explaining that values are pinned in tests rather than quoted because prose goes stale silently.
